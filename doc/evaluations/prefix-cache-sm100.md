- 所有 GPU 任务在远端独立 tmux 中运行。性能用干净代码；打印命中长度的临时探针在性能结束后才热改进去。实验结束已停止自己的服务和会话，GPU 6 显存回到 0 MiB。

## 结论

**前缀缓存在完整模型上确实可用，首 token 有明确加速，三个故障植入都被检查发现。** 实际调度日志确认了长提示词、decode 检查点、分叉前缀三种命中。BF16 下，冷跑和缓存命中会出现不同的贪心文本；SGLang 对照也有这种现象，具体数值见下文。

两项需要随这份性能结果一起保留：

1. **BF16 的冷跑和缓存命中文本存在差异。** 10 组边界长度中，RSInfer 有 **4 组**贪心文本变化，SGLang 有 **2 组**；同输入逐步比较的 logits 最低余弦相似度为 **0.9998**，发生 top-1 变化时原来的领先分差只有 **0–0.0625**。
2. **原有 GPU 测试仍是 2 passed / 1 failed，负例断言需要修正。** 正确检查点的 temporal 误差为 **0.30%**，满足原测试的 5% 要求；故意错一个 token 的负例误差为 **14%**，已经比正例大约 47 倍，但没有达到测试写死的 **50%** 下限，因此测试失败。应调整这个负例条件，保留正确状态的误差要求。补充的完整模型检查覆盖了该测试因提前失败而未执行的末尾检查点分支。

原有 `tests/gpu/test_prefix_cache.py` 通过 `QWEN38_MODEL` 使用完整真实 checkpoint：

- **Graph 状态跟踪通过**：graph 和 eager 的采样相同；跟踪槽与运行槽逐位相同，未选中的槽保持不变，下一次不跟踪时 mask 被清掉。
- **恢复后继续计算通过**：恢复位置 128 的状态，再算两个 token，状态相对误差约 **0.93%**；不恢复的对照为 **94%**，采样 token 与完整提示词一致。
- **中间检查点测试失败在负例门槛**：正确保存到 128 的 conv/temporal 相对误差为 **0.85% / 0.30%**，均小于原要求 5%；错一个 token 的对照为 **57% / 14%**。原测试要求两个负例误差都超过 50%，因此 temporal 的 14% 触发失败。这个下限来自四层随机权重，不适合作为所有真实权重的条件。

### 待修测试：负例的固定 50% 下限

失败测试为 `test_a_state_kept_inside_or_at_the_end_of_a_prefill_chunk_is_the_state_computed_up_to_there`，断言是：

```python
assert max(kept) < 5e-2 and min(off) > 0.5
```

| 状态分量 | 正确检查点误差 `kept` | 错一 token 的负例误差 `off` | 负例 / 正例 |
|---|---:|---:|---:|
| conv | 0.85% | 57% | 约 67× |
| temporal | 0.30% | 14% | 约 47× |

`max(kept) < 5e-2` 已满足，失败发生在 `min(off) > 0.5`。不同真实权重下，错位带来的误差大小会变化；负例的作用是确认检查能区分正确状态和错误状态。这里 14% 与 0.30% 已有明显分离，固定要求超过 50% 会误拒正确实现。

**修复建议：保留正例误差小于 5% 的要求，把负例改成逐分量检查相对正例的分离度，例如至少大 10 倍，并在四层随机权重和 64 层真实权重上验证。** 本轮未修改这个测试，原套件结果按 **2 passed / 1 failed** 保留；A/B/C 补充验证单独报告。

## BF16 输出差异

同一提示词的第一次冷跑和第二次请求，8-token 文本完全相同的组数：

| 配置 | 相同 / 总数 | 有变化的输入长度 |
|---|---:|---|
| RSInfer 关缓存 | 10/10 | — |
| RSInfer 开缓存，overlap 开或关 | 6/10 | 65、127、129、3088 |
| SGLang 关缓存 | 10/10 | — |
| SGLang 开缓存 | 8/10 | 127、3088 |

进一步在真实 64 层 GPU worker 上比较冷跑和缓存恢复：后续每一步喂同一个 token，避免先前采样分叉影响数值比较。

| 输入长度 | 复用长度 | 8 步 logits 最大相对 L2 误差 | 最低余弦相似度 | top-1 相同 |
|---:|---:|---:|---:|---:|
| 65 | 64 | 0.70% | 0.999981 | 8/8 |
| 127 | 64 | 1.91% | 0.999871 | 7/8 |
| 129 | 128 | 2.14% | 0.999800 | 7/8 |
| 3088 | 3072 | 0.85% | 0.999974 | 7/8 |

发生 top-1 变化的三步，冷跑第一名领先第二名仅为 0.0625、0、0。小幅数值变化就足以改变贪心选择，随后整段文本会分叉。Triton 的中间 `h` 检查点使用 BF16，且命中后的计算形状不同；本地 SGLang 的 Triton GDN 同样没有 FP32 `track_state` 快照能力。这次确认了功能、状态误差和性能，也保留了实际观察到的文本差异。
