# 热更新耗时：`apply` 对比 vLLM、SGLang（2026-11-10，n1，Qwen3.8-27B）

RSI 里常见的改动有三类：改代码、改配置、换权重。这里测的是三个框架各做一次这样的更新要多久：我们用 `apply`；vLLM 和 SGLang 用各自对应的更新方法，改代码和改配置都只能重启，换权重有不重启的接口。只选三个框架都支持的功能和配置，并且都只测空闲引擎，即纯更新成本。

网上没有现成的热更新耗时基准。改代码的 case 参照了 SEIS（arXiv 2610.04646）里 agent 实际改过的那几类地方：kernel、attention、采样、调度、模型。

## 环境和设置

- 机器：n1（`gpu-node-n1`），SM100 180 GB，每家单独用一张卡；测量串行进行，互不重叠。
- 模型：`/models/Qwen3.8-27B`，bf16，TP1，eager，只跑文本，权重先读进页缓存。
- 三个框架：
  - 我们：master `efce690`，用 `deploy/qwen38.py serve` 起引擎。B7 另用 `07442d6` 重跑（合完 #46、还没合 #45，没有 CUDA graph），见下面的说明。
  - vLLM 0.26.0：`--enforce-eager --language-model-only --no-enable-prefix-caching --no-async-scheduling`，attention 是 FlashInfer。
  - SGLang 0.5.23：`--disable-cuda-graph --language-only --disable-radix-cache --disable-overlap-schedule --attention-backend flashinfer`。SM100 上默认的 `trtllm_mha` 第一次请求时要从外网下载 cubin，n1 下载不了，所以改用 flashinfer。
- 三家参数对齐：并发 64、长度 4096、chunked prefill 2048、显存比例 0.85、页 16、overlap 关（只有 B1 打开）。
- 改代码的 case 用最小改动：在对应文件末尾加一行注释，每次重复都换一个不同的注释。
- 改配置的 case 在新值和原值之间来回切，每次切换都计时。
- **T_ready**：从发出更新到能用新代码或新配置服务。
  - 我们：`apply` 命令从启动到返回 committed 的墙钟时间，包括客户端给工作区算哈希、上传文件。
  - vLLM / SGLang：重启类从发 SIGTERM 开始，到新进程能服务为止；换权重类就是接口调用本身的耗时。
- **T_first**：从发出更新到一个 1 token 的 greedy 请求返回。各项都比 T_ready 多 0.1–0.3 秒，结论一样，这里不单列。
- 每个 case 跑 5 次，报中位数 [最小, 最大]。每次更新后都发一个 16 token 的 greedy 请求，和更新前对比：三家 300 次全部相同。

- A1：`policies.fcfs`（连带 `core.sched`）；A2：`core.sched`；A3：`layers.sampler`；A4：`kernels.reference`。

## 说明：哪些数可能受了干扰

- **†**：vLLM 的 A1 第 1–2 次、A5 第 1–3 次，和 #46 的修复验证同时跑过。那次验证在同一台机器的另外两张卡上起引擎、读 55 GB 权重，可能影响了这几次重启的耗时。没有补测。
- **‡**：SGLang 的 B4 有一次是 256 秒的离群值，原因没查，中位数不受影响。
- **§**：vLLM 对这个混合模型会自己把 attention 的 block size 改成 784（日志里有 "Setting attention block size to 784 tokens"），所以它的 B6 只是一次重启，配置实际没有变。
- **¶**：B7 在 `efce690` 上，改成 bf16 的 3 次全部因 CUDA OOM 撤回，原因见 `doc/framework-bugs/2026-11-10-gdn-ssm-dtype-rebuild-oom.md`。表里是 #46 修复后用 `07442d6` 重跑的 5 次：5 次都提交，输出都相同；其中改成 bf16 的 3 次是 1.39、1.15、1.09 秒。

## 结论

- **改代码、改配置**（A1–A8、B1–B7）：我们在原地重载单元，1.0–2.2 秒，其中约 0.7–0.9 秒是 `check+plan`。vLLM 和 SGLang 只能重启，分别约 93–104 秒和 64–72 秒，比我们慢 32–98 倍。
- **A9 改权重加载代码**：我们要重读 checkpoint，27.6 秒，仍比它们重启快 3–4 倍。
- **A10 改框架本体**：三家都要冷启动，我们 37.6 秒，比 vLLM 快 2.6 倍、比 SGLang 快 1.8 倍。
- **C1 换权重**：三家都有不重启的接口，24.8–26.6 秒，基本打平，时间都花在读 55 GB 权重上。

测试脚本和原始数据（每次运行的 JSONL 和日志）不在仓库里。
